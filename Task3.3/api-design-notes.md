# Комментарий к спецификации `GET /api/v1/appointments`

Спецификация: [`appointments-api.yaml`](appointments-api.yaml).

## Пагинация

Выбрана пагинация по смещению: `limit` (по умолчанию 20, максимум 100) и `offset` (по умолчанию 0), в ответе — блок `pagination` с `total`, `limit`, `offset`, `next`, `prev`.

Почему так:

- выборка мала и ограничена по природе — у пациента единицы предстоящих записей и десятки в истории, поэтому дорогие большие смещения здесь не возникают;
- смещение позволяет открыть любую страницу истории, курсор — только последовательный проход;
- параметры читаемы в логах и трассировке, запрос легко воспроизвести при разборе инцидента.

Для коллекций с неограниченным ростом (журнал результатов исследований, лента уведомлений) в контрактах предусматривается курсорная пагинация — она устойчива к постоянным вставкам в начало выборки. В нашем случае это не нужно.

## Версионирование

Мажорная версия зафиксирована в пути: `https://api.zdorovie-plus.ru/api/v1/...`; полная версия контракта (`1.0.0`, семантическое версионирование) указана в `info.version`.

Почему версия в URL:

- API Gateway маршрутизирует трафик разных версий по пути, без разбора заголовков — это же позволяет выкатывать версию 2 постепенно;
- мобильные клиенты не обновляются принудительно: в магазинах одновременно живут несколько версий приложения, и старое приложение продолжает работать с `/v1`, пока версия поддерживается;
- версия видна в логах, трассировке и ссылках, что упрощает разбор инцидентов.

Версия в заголовке или media type отвергнута: контракт формально чище, но версия теряется в логах и ссылках и усложняет маршрутизацию; версия в query-параметре — неотличима от фильтра и теряется при редиректах.
